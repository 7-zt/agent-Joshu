# 设计-验证-执行循环

多代理协作模式：OMP 设计 → Codex 验证 → Claude 执行。

---
description: 三阶段多代理协作：设计阶段产出方案与证据，验证阶段独立审查，执行阶段落地并反馈结果。
---

## Goal

通过三个独立代理的串行协作，确保方案质量：设计者产出方案与证据基础，验证者独立审查方案严谨性与证据完整性，执行者落地方案并验证实际效果。

## 输入

**任务描述**（`$TASK`）：
- 性能分析任务：目标指标、当前状态、约束条件
- 部署排障任务：故障现象、环境信息、已尝试操作
- 调研任务：调研问题、范围、输出要求

**工作区状态**（`$CONTEXT`）：
- 相关文件路径
- 历史基线（如有）
- 任务材料目录（如有）

## 证据要求

### 设计阶段（Claude）

- 性能分析：基线是否存在、测量方案、预期证据类型
- 部署排障：环境快照完整性、假设可证伪性、分层检查点
- 调研：来源分级、论断分类、未解决问题显式列出

### 验证阶段（Codex）

**只读审查**，输出 PASS/FAIL + 具体问题：

检查项：
- 证据完整性：是否所有断言都有证据支撑
- 论断分类：是否区分事实/推断/假设/建议
- 版本敏感内容：是否标注版本或声明"需确认版本"
- 自包含性：方案是否可被任意 Agent 执行（无隐含依赖）
- 停止规则：是否遵守 Skill 的停止规则（如无基线不断言瓶颈）

**输出格式**：
```
## 验证结果：[PASS / FAIL]

### 证据完整性
- ✓/✗ 项目1
- ✓/✗ 项目2

### 论断分类
- ✓/✗ ...

### 版本敏感内容
- ✓/✗ ...

### 修正建议（FAIL时）
1. 具体问题描述
2. 建议修正方式
```

### 执行阶段（OMP）

- 按方案执行，记录每步结果
- 验证预期与实际是否一致
- 发现偏差立即停止并报告

## 只读边界

**验证阶段严格只读**：
- 不修改设计方案
- 不重做设计
- 不执行任何命令
- 只输出审查结论与修正建议

**执行阶段授权边界**：
- 按 L0-L3 分级（见 inference-ops Skill）
- L2/L3 需用户当次确认

## 失败条件

**设计阶段失败**：
- 无法获取必要输入信息
- 任务超出 Skill 能力范围

**验证阶段失败**：
- 发现证据缺失
- 发现论断分类错误
- 发现违反停止规则
- 发现版本敏感内容无标注

**执行阶段失败**：
- 命令执行与预期不符
- 发现设计方案中的错误假设
- 环境变化导致方案不适用

失败时停止流程，回到设计阶段修正。

## 输出格式

### 设计阶段输出

```markdown
## 设计方案

### 目标与约束
- ...

### 证据基础
- 已有基线：[是/否]
- 环境快照：[完整/部分/缺失]

### 方案
1. 步骤1（L0/L1/L2/L3标注）
   预期：...
   证据：...

2. 步骤2
   ...

### 验证标准
- 如何判断成功
- 如何判断失败

### 不确定性
- 待确认项
- 风险点
```

### 执行阶段输出

```markdown
## 执行结果

### 步骤记录
- [✓/✗] 步骤1
  实际：...
  与预期一致/偏差：...

- [✓/✗] 步骤2
  ...

### 验证结果
- [✓/✗] 验证标准1
- [✓/✗] 验证标准2

### 发现的问题
- ...

### 后续建议
- ...
```

## $ARGUMENTS

任务描述与上下文的具体内容。

示例：
```
任务：分析 vLLM 部署吞吐低于预期的原因
上下文：
- 配置文件：/path/to/config.yaml
- 启动日志：/path/to/logs/
- 预期吞吐：100 tok/s
- 实际吞吐：45 tok/s
```

## 使用方式

```bash
# 设计阶段（Claude）
herdr start claude --prompt "$(cat omp/prompts/design-verify-execute.md)" \
  --args "任务：... 上下文：..."

# 验证阶段（Codex，设计完成后）
herdr start codex --prompt "验证设计方案 /path/to/design-output.md，按 omp/prompts/design-verify-execute.md 的验证标准"

# 执行阶段（OMP，验证通过后）
herdr start omp --prompt "执行设计方案 /path/to/design-output.md"
```

## 注意

- 三阶段必须串行，不跳过验证
- 验证失败必须修正后重新验证
- 执行失败不要盲目重试，回设计阶段分析原因
- 每阶段产出写入任务材料目录，可审计
