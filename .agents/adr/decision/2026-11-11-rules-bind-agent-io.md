# ADR 决定：Agent 输入输出以规则目录为强制依据

## 背景

2026-11-11 用户启动仓库规范化，第一条要求：模型在本仓库工作时的每一次输入输出都必须参考 `.agents/rule/` 中的规定，并把该要求写入 ADR。

`.agents/rule/` 定位是工作规则层（见 `.agents/rule/document-writing.md` 的分层），现有五个规则文件：

- `document-writing.md`：文档分层、格式与 MR、Issue 正文写法
- `code-management.md`：分支、提交、合并与任务材料
- `testing.md`：测试目标、组织、断言与覆盖
- `coding-notes.md`：工程判断准则
- `code-style-python.md`：Python 风格、类型与导入

两个事实使该要求成为边界变化：规则目录此前未被 `AGENTS.md` 引用，模型会话不会自动加载，规则对模型没有强制途径；规则文件引用了本仓库不存在的设施（`servio/` subtree、`uv`、`make`、`.gitlint`、GitLab MR），部分条目与现行决定冲突（如 `code-style-python.md` 的 Python 3.12+ 与 memtrace 的 Python 3.10+ 零依赖契约）。强制执行前必须先给出冲突处理规则。

## 决定

- `.agents/rule/` 是约束模型输入输出的强制规则层。模型在本仓库工作的一切输入理解与输出产物，包括代码、文档、提交信息、报告与会话答复，都必须先对照该目录现行规则。
- `AGENTS.md` 引用规则目录作为加载入口：模型会话开始先读该目录全部规则文件。
- 冲突处理：
  - 规则与现行 ADR 决定冲突时，以 ADR 决定为准，冲突条目记为待修订，在后续规范化步骤中消解。
  - 规则条目依赖本仓库不存在的设施时，该条目不适用，其余条目仍然有效。
- 规则文件自身的修订是文档更新，不强制走 ADR；只有改变本决定边界时才更新本决定。

## 真实替代项

- 把规则并入 `AGENTS.md` 单文件。被拒：`AGENTS.md` 定位是导航与非显然约束，复制工作规则违反文档分层「同一内容只放一层」。
- 只保留规则目录，不做强制引用，依赖模型自觉发现。被拒：模型不会读未被引用的目录，规则成为死文档。
- 先逐条改写规则适配本仓库，再立强制依据。被拒：用户要求先立依据；适配作为后续规范化条目，冲突处理条款在过渡期兜底。

## 后果

- ✓ 模型输出有统一、可对照的规则依据，规范化后续条目有落点
- ✓ 规则演进只改 `.agents/rule/`，`AGENTS.md` 不随规则内容变动
- ✗ 过渡期内规则含不适用的条目，模型每次输出要判断适用性
- ✗ 每个会话开始多一次规则加载

## 重审条件

规则目录完成本仓库适配、待修订条目消解后；规则膨胀到需要按领域拆分时；出现 lint 或 hook 等工具化检查能替代模型自觉对照时。
