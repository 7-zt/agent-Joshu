# 架构决定记录（ADR）

ADR 记录影响长期边界的决定及其理由与契约。不是进度日志、发布说明或临时计划。

## 何时写 ADR

规划需求前先搜索既有提案与现行决定，判断该需求是新增无关能力、无冲突地扩展现行决定，还是与现行决定冲突。

满足以下条件才创建或更新 ADR：存在真实替代方案，且选择改变长期边界（架构、所有权、公共/宿主契约、持久格式、兼容性、仓库级开发与发布策略）。

不创建：本地 bug 修复、机械重构、普通文档更新、状态汇报、临时计划（除非其改变上述边界）。

## 位置与文档类型

ADR 根目录为 `.agents/adr`：

```text
.agents/adr/proposal/yyyy-mm-dd-english-slug.md
.agents/adr/decision/yyyy-mm-dd-english-slug.md
.agents/adr/rejected/yyyy-mm-dd-english-slug.md
.agents/adr/archived/yyyy-mm-dd-english-slug.md
```

- `proposal/` 生效提案；`rejected/` 被拒提案；`decision/` 现行决定；`archived/` 归档决定。目录同时表达类型与状态，文件内不写 Status 字段。
- 文件名日期为首次提案日期，移动不改。英文短 slug；完整文件名（含日期与扩展名）不超过 60 字符。
- 四个生命周期目录始终保留在 git 中（含 `.gitkeep`）。

动作用短语：「创建决定」「更新决定」「反向决定」。反向决定新建完整的决定并在头部加 `反向决定：<旧决定文件>`；旧决定头部加 `被反向决定：<新决定文件>` 后移入 `archived/`。

## 单用户生命周期

- 提案的批准、拒绝、决定归档由用户本人当次明确确认；Agent 可在授权变更内起草与维护 ADR，但不得自行做生命周期决定。
- 获批提案先合入主线，实现自结果主线开始；实现完成后创建新决定、无冲突地更新现行决定、反向冲突决定，并在同一变更中移除已消费的提案（git 历史保留其理由）。
- 被拒提案移入 `rejected/`，追加 `## 拒绝原因` 后冻结，仅允许修复事实性链接。

## 提案格式

```markdown
# ADR 提案：<标题>

## 背景
## 提议
## 真实替代项
## 验收标准
## 风险
```

## 决定格式

```markdown
# ADR 决定：<标题>

## 背景
## 决定
## 真实替代项
## 后果
## 重审条件
```

- 更新决定：新内容与现行决定无冲突时，在文末 `## 变更` 节下按日期三级标题追加。
- 反向决定：不改写现行决定来表达冲突选择；新建提案点名所有要反向的决定，实现后把仍有效的规则与新选择合并为完整新决定。
- 归档决定：保持决定格式，头部加 `归档：YYYY-MM-DD`，冻结；现行文档不得再将其引用为现行依据。

## 作者纪律

- 「真实替代项」只记录起草时已存在、或讨论中真实进入选择的选项；不编造凑数。无可写条目时写「无」。
- 「风险」必须描述采用该方案可能导致的可信危害结果；约束、需求、验收标准本身不是风险。无可写条目时写「无」。
- 「背景」陈述考虑或采纳该选择的具体理由。
