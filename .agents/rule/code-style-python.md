# Python 代码风格

## 基础

- Python 3.12+，使用 `type` 别名和 PEP 695 泛型语法。
- 行宽 120，使用 ruff 检查和格式化。
- 使用 `uv run --no-sync` 执行工具，禁止直接运行系统 `python`。
- 异步操作使用 anyio。
- 不使用 `from __future__ import annotations`。需要前向引用时使用 `TYPE_CHECKING` 和字符串字面量。
- 禁止相对导入。

## 命名

- 模块、函数、变量使用 `snake_case`。
- 类、协议、类型别名使用 `PascalCase`。
- 常量使用 `UPPER_SNAKE_CASE`。
- 私有实现使用前导下划线，只在所属包内部使用。
- 布尔值使用 `is_`、`has_`、`can_`、`allow_` 等肯定式前缀。
- 名称表达职责，不使用 `data`、`info`、`manager` 这类无法区分上下文的泛化词，除非它是既有协议的一部分。

## 类型

- 公共函数、方法、模块级变量写完整类型注解。
- 使用 `collections.abc` 的 `Callable`、`Iterable`、`Sequence`，不优先使用 `typing` 同名类型。
- 使用 `Protocol` 表达结构契约，使用 `runtime_checkable` 只在确实需要运行时检查时。
- 使用 `msgspec.Struct` 表达不可变数据，使用 pydantic `BaseModel` 表达配置和需要校验的输入。
- 避免 `Any`。必须使用时，把范围限制在边界适配层，并在调用点收窄。
- 使用 `cast` 时说明无法由类型系统表达的原因，不用它掩盖真实类型错误。

## 导入

- 标准库、第三方、本仓库模块分组，组间空一行，由 ruff 排序。
- patch 公共符号统一从 `servio_sglang.patch` 导入；patch 私有实现在 `patch/` 内部使用。
- runtime 代码导入 `servio_sglang` 与第三方包，通知由 `servio_sglang.sentinel` 发送。
- 循环依赖先通过归属调整、合并或上层编排消除。局部导入只用于真实加载时机，例如避免导入即改写上游对象；它不作为架构环的豁免。

## 函数与类

- 函数保持单一职责，参数过多时先确认是否缺少一个明确的数据结构。
- 优先返回结果，不通过修改外部可变状态表达成功或失败。
- 异常用于无法继续的情况，不用异常做正常分支。
- 不写防御性分支处理不会发生的输入。需求没有定义的输入直接报错。
- 不使用可变默认参数。
- 数据对象优先不可变。需要更新时使用 `msgspec.structs.replace` 或显式构造新对象。

## 配置

- 配置模型放在 `settings.py` 或所属领域的 `config.py`。
- 配置字段写 `Field(description=...)`，说明单位和默认值含义。
- 配置读取集中在 `load_settings()`；业务代码不直接读环境变量。发送时的部署信息等进程外事实属于运行时采集，由所属领域显式读取，不缓存进配置快照。
- 不测试配置模型默认值和来源优先级。

## 文档字符串

- 公共模块、类、函数写中文文档字符串。
- 第一行说明职责，不重复函数名。
- 参数和返回值在签名已经清楚时不重复描述；存在单位、边界或副作用时补充说明。
- 注释解释原因和约束，不逐行翻译代码。

## 测试

- pytest，函数风格。
- 测试文件和函数使用 `test_` 前缀。
- 测试函数名不超过 40 字符，细节放在文档字符串。
- 断言对外行为，不绑定私有方法和内部状态。
- 测试规则见 [测试](./testing.md)。
