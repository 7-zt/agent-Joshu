# 完整模式

重型系统性闭环。**仅用户显式触发**（排障：「系统排查」「完整诊断」「从头排查」；性能：「完整分析」「系统性性能审查」「全面 profiling」），或快速模式升级进入。分阶段推进，高严重度结论自我复核。

## 共同原则

- 动笔前先登记（问题登记 / 上下文登记），全程记录。
- 分层推进，只在上一层证据指向下一层时下探；不做无目标的全量扫描或全量 profiling。
- 每个候选结论都是假设：写出预期信号 → 检查证据或设计最小验证 → 记录结果。未验证的假设保留为假设，不得升级为结论。
- 高严重度结论自我复核：重读证据、考虑合理解释（是否故意配置？是否测量伪影？是否混杂变量？），写明置信度。经不起复核的降级或删除。
- 建议直接报告；执行修改需另行明确授权（L0-L3 分级见 [SKILL](../SKILL.md)）。

## 排障轨步骤

### 1. 问题登记

故障现象（预期 vs 实际）、影响范围、开始时间与变更历史（「之前好的吗？中间改了什么？」）、复现条件。

### 2. 完整环境快照

按 [evidence-and-snapshot](../references/evidence-and-snapshot.md) 采集：硬件、OS、驱动、软件版本、容器、配置文件关键部分。

### 3. 复现确认

最小化复现：剥离无关组件，找到能稳定触发（或统计出触发率）的最小路径。复现不稳定时记录触发条件与频率，不假装可稳定复现。方法见 [layered-diagnosis](../references/layered-diagnosis.md) 的复现与二分一节。

### 4. 分层扫描

按 硬件 → 驱动 → 系统 → 容器/运行时 → 依赖 → 服务 → 应用 逐层检查（各层检查清单见 [layered-diagnosis](../references/layered-diagnosis.md)），每层：

- 该层的健康检查命令（L0 只读优先）；
- 异常信号 → 假设 → 验证 → 记录；
- 该层干净则明确记录「已排除」再上移/下移。

### 5. 变更三问

对每个可疑点问：最近改过吗（配置/版本/环境）？文档说应该怎样（引官方文档，标注版本）？最小验证是什么？

### 6. 根因确认

候选根因必须通过「反向验证」：按根因推导应有其他可观测现象，检查它们是否成立。成立才升级为根因；只解释了原始报错不算。

### 7. 解决与收尾

解决方案按 L0-L3 分级授权执行；执行前准备回退（见 [layered-diagnosis](../references/layered-diagnosis.md) 的解决回退与收尾一节）；执行后验证原始复现路径已消除；记录 workaround 的临时性与触发条件。

## 性能轨步骤

### 1. 上下文登记

审查目标（哪个子系统/哪个指标）、必读（配置、启动参数、日志）、可选上下文（相邻代码、历史调优记录）、待解问题。

### 2. 基线审计

检查既有基线是否合格（见 [benchmark-protocol](../references/benchmark-protocol.md)：负载定义、环境记录、统计口径、样本数）。不合格的基线不能作为对比锚点，先补测（需授权）。

### 3. 分层剖析

自顶向下逐层收敛，每层记录证据：

1. 服务级：吞吐/延迟/错误率的总体形态（饱和、抖动、退化曲线）。
2. 引擎级：调度、批组成、队列、缓存命中形态（按引擎提供的指标）。
3. 算子/内核级：profile 数据（nsys / ncu / 引擎自带 profiler，按可用性选择；解读方法见 [bottleneck-localization](../references/bottleneck-localization.md)）。
4. 资源级：GPU 利用率、显存带宽、通信、功耗、内存交换。

### 4. 假设-验证循环

每个候选瓶颈作为一个假设：写出预期信号 → 检查证据或设计最小验证 → 记录结果。未验证的假设保留为假设，不得升级为结论。

### 5. 自我复核

见共同原则。每个高严重度结论写明置信度与剩余不确定性。

### 6. 改动建议与授权

建议直接报告；执行修改（参数、配置、版本变更）需另行明确授权。跨多文件的改动给计划与成本，由用户决定。

## 输出格式

排障轨：

```text
结论
- 根因: …（已反向验证）
  证据链: 每步的命令五元组
  解决: 步骤 + 验证结果 + 回退 + 风险

分层记录
- 硬件: [排除/异常+证据] …
- 驱动: …
- 系统: …
- 容器: …
- 依赖: …
- 服务: …
- 应用: …

复现
- 最小复现路径 + 触发率

遗留
- workaround 清单（临时性说明）、待确认项
```

性能轨：

```text
结论
- [严重度, 置信度] 主题
  证据: 支持证据与反证，剩余不确定性
  判断: 机制解释
  建议: 最小充分改动 + 预期收益区间 + 验证方法 + 回退方案

测量记录
- 已有基线的合规性判定；本次补测的环境/负载/统计（引用归档路径）

待验证假设
- …（含验证草案）

待用户决定
- …
```

## 停止规则

- 根因未反向验证不写「根因」；未验证假设不写成结论；单变量原则下的归因才有效。
- 不跳层；每层排除要有记录；不为收敛而编造解释；「未定位 + 下一步计划」是合法结论。
- 不自动执行有负载命令或环境变更。
- 证据不足时说不足，不包装成确定。
