# 快速模式

默认模式，低成本高信号。故障轨针对单一明确错误；性能轨针对单一性能问题或小 diff 自检。目标是少量、高置信的结论，不追求覆盖，倾向放过「足够好」。

## 触发

- 未指定模式时的默认。
- 故障轨：单一报错、局部问题、现象明确。
- 性能轨：日常自检、小 diff、单一明确问题（如「延迟高」）。
- 范围是整系统或说不清时，请用户收窄或升级完整模式。

## 前置条件

- 故障轨：有具体错误信息或失败现象。无报错、说不清现象时，先帮用户把现象描述成可核查形式（何时、何地、预期 vs 实际）。
- 性能轨：有具体目标：一个现象、一个 diff、一个配置变更。
- 只读。不修改被测系统与环境。

## 步骤：故障轨

1. 提取错误关键行（含时间戳与上下文），原样引用。
2. 采最小环境快照（只采与报错相关的类别，见 [evidence-and-snapshot](../references/evidence-and-snapshot.md)）。
3. 按报错信号直接检查对应层的高概率原因（最多 3 个假设），每个假设设计一个最小验证。
4. 验证通过 → 给根因 + 解决方案；不通过 → 报告已排除项，建议升级完整模式。

## 步骤：性能轨

1. 建立项目事实：读配置与启动参数，看环境（`nvidia-smi` 等只读命令）。
2. 判定证据状态：是否已有可信基线（满足 [benchmark-protocol](../references/benchmark-protocol.md) 的证据集）。
3. 有基线：针对现象检查最多 5 个高信号假设（批处理是否打满、KV cache 是否触顶、长度分布是否异常、是否处于降级路径、资源竞争）。
4. 无基线：不做瓶颈结论；输出待验证假设清单 + 每个假设的验证命令草案 + 建议的基线采集方案。

## 输出格式

故障轨：

```text
现象
- 原样错误引用 + 位置

已验证结论（0-3 条）
- 结论: …
  证据: 命令五元组 / 日志行
  解决: 步骤 + 预期结果 + 回退 + 风险（标注 L2/L3 需授权）

已排除
- 假设 → 排除证据

待确认
- …（含需要的下一步验证）
```

性能轨：

```text
结论（仅限有证据的，0-5 条，零条有效）
- [置信度] 主题
  证据: 命令输出/配置项/日志片段（带位置）
  判断: 为什么指向该结论，不确定性是什么
  建议: 最小充分动作 + 验证方法

待验证假设（无基线或证据不足时）
- 假设: …
  验证: 命令/测量草案（标注需要的授权）
  预期: 验证后能区分什么

备注
- 降级、工具可机械发现、需用户决定的事项
```

## 停止规则

- 故障轨：3 个假设验证完仍未定位就升级完整模式，不继续盲试。
- 性能轨：上限 5 条结论，保留最关键的；不编造发现凑数，干净的系统零发现。
- 不猜根因；每个结论挂证据；不把外部基准数字当本机结论，引用必标「未本机复测」+ 来源 + 版本。
- 不推荐未在目标环境验证的参数。
- L2/L3 命令给文本待确认，不自动执行。
