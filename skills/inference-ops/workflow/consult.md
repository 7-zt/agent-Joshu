# 咨询与调研模式

无故障要排查、无测量要评判时的模式。**咨询轨**：用户在问「怎么做/选哪个」，帮助设计方案与取舍并收敛。**调研轨**：用户要结构化、证据优先的技术调研与学习报告。

## 咨询轨

### 触发

- 方案讨论：「批大小怎么定？」「要不要上量化？」
- 工具对比：「vLLM 和 TensorRT-LLM 在我这个场景怎么选？」
- 调优思路：从哪里入手、按什么顺序。

### 步骤

1. 理解约束：目标指标（吞吐/延迟/显存/成本，哪个优先）、硬件与预算、可接受的改动范围。关键事实缺失就问。
2. 给出真实有差异的 2-3 个选项：各自是什么、代价、什么时候赢。用对比表呈现平行选项。
3. 每个选项中的性能预期用区间 + 不确定性表达，标注依据类型（本机证据 / 外部基准「未本机复测」 / 理论推导）。
4. 收敛：明确推荐一个并说理由（对应第 1 步的约束），说清代价。用户可推翻。
5. 给出下一步：建议的首个验证测量（满足 [benchmark-protocol](../references/benchmark-protocol.md) 的最小版本）。

### 停止规则

- 咨询不修改任何文件与环境。
- 涉及具体引擎参数行为且版本不明时，说「需确认版本」，不猜。
- 不把「取决于 X」硬拗成确定答案；命名 X 并问。
- 用户接受方案转向实际工作时，建议走快速/完整模式，不静默切换。

## 调研轨

结构化、证据优先的调研流程，产出可复用的学习报告。适用于：学习新推理引擎/优化技术、工具与方案对比、技术细节深挖、为决策收集证据。

### 步骤（严格遵循）

1. **澄清调研问题**：调研什么、多深、优先角度、目的（学习/决策/对比/验证）。
2. **识别关键维度**：拆子主题、列问题清单、标背景知识。
3. **广泛探索**：先宽后深；从初步结果识别子主题与不同视角；**不让头一两个来源定义整个方向**。
4. **深度挖掘**：每个维度定向搜索；变换关键词组合；通读重要来源全文（不只摘要）；来源提到的关键资源跟进。
5. **验证与分类**：覆盖多样信息类型；多源同说视为同一证据链的一部分，整合交叉验证（警惕转载链伪装成多源）；支撑关系不清不写定论。
6. **综合输出**：按 [reporting](../references/reporting.md) 的调研报告骨架输出；论断逐条标注分类；来源快照归档。

### 来源分级与快照

见 [reporting](../references/reporting.md)：一手来源 > 二手来源 > 仅作线索；重要来源默认保存快照（原文或详细摘要 + URL + 作者 + 日期），归档到报告的 sources/ 子目录，不依赖网页当前状态做后续审计。

### 子代理

大型调研尽量用子代理并行收集处理；超过并发上限就排队；出错纠正优先于终止，不可恢复时保存当前状态。

### 停止规则

- 证据不足不下定论；不把二手当一手引用；不把宣传当事实。
- 完成请求范围即停止，不仅因「还有更多来源」无限扩展。
- 不编造来源；不隐藏「没找到答案」；不把推断伪装成事实。
- 调研中发现值得复用的引擎知识时，询问用户是否按 [knowledge-base](../references/knowledge-base.md) 协议入库。
