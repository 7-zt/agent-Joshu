# 快速分析：性能

默认模式。针对单一性能问题或小范围调优的低成本高信号检查。优化目标是少量、高置信的结论，不追求覆盖。倾向放过「足够好」。

## 触发

- 未指定模式时的默认。
- 日常自检、小 diff、单一明确问题。

## 前置条件

- 有具体目标：一个现象（「延迟高」）、一个 diff、一个配置变更。范围是整系统或说不清时，请用户收窄或改走完整分析。
- 只读。不修改被测系统。

## 步骤

1. 建立项目事实：读配置与启动参数，看环境（`nvidia-smi` 等只读命令）。
2. 判定证据状态：是否已有可信基线（满足 benchmark-protocol 的证据集）。
3. 有基线：针对现象检查最多 5 个高信号假设（批处理是否打满、KV cache 是否触顶、长度分布是否异常、是否处于降级路径、资源竞争）。
4. 无基线：不做瓶颈结论；输出待验证假设清单 + 每个假设的验证命令草案 + 建议的基线采集方案。
5. 输出。

## 输出格式

```text
结论（仅限有证据的，0-5 条，零条有效）
- [置信度] 主题
  证据: 命令输出/配置项/日志片段（带位置）
  判断: 为什么指向该结论，不确定性是什么
  建议: 最小充分动作 + 验证方法

待验证假设（无基线或证据不足时）
- 假设: …
  验证: 命令/测量草案（标注需要的授权）
  预期: 验证后能区分什么

备注
- 降级、工具可机械发现、需用户决定的事项
```

## 停止规则

- 不编造发现凑数；干净的系统零发现。
- 不把外部基准数字当本机结论；引用必标「未本机复测」+来源+版本。
- 不推荐未在目标环境验证的参数。
- 上限 5 条结论，保留最关键的。
- 不自动执行有负载或改环境的命令；给出命令供确认。
