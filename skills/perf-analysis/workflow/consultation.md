# 咨询模式：性能

咨询模式。用户在问「怎么做/选哪个」，不是「哪里错了」。没有测量要评判，帮助设计方案与取舍并收敛。

## 触发

- 方案讨论：「批大小怎么定？」「要不要上量化？」
- 工具对比：「vLLM 和 TensorRT-LLM 在我这个场景怎么选？」
- 调优思路：从哪里入手、按什么顺序。

## 步骤

1. 理解约束：目标指标（吞吐/延迟/显存/成本，哪个优先）、硬件与预算、可接受的改动范围。关键事实缺失就问。
2. 给出真实有差异的 2-3 个选项：各自是什么、代价、什么时候赢。用对比表呈现平行选项。
3. 每个选项中的性能预期用区间+不确定性表达，标注依据类型（本机证据 / 外部基准「未本机复测」 / 理论推导）。
4. 收敛：明确推荐一个并说理由（对应第 1 步的约束），说清代价。用户可推翻。
5. 给出下一步：建议的首个验证测量（满足 benchmark-protocol 的最小版本）。

## 停止规则

- 咨询不修改任何文件与环境。
- 涉及具体引擎参数行为且版本不明时，说「需确认版本」，不猜。
- 不把「取决于 X」硬拗成确定答案；命名 X 并问。
- 用户接受方案转向实际工作时，建议走快速/完整分析，不静默切换。
