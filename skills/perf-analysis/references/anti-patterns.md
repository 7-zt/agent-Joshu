# 性能分析反模式

常见错误做法、为何错误、如何识别、如何避免。

## 反模式清单

### 1. 无基线改动

**现象**：「优化后快了」，但没测优化前。

**为何错**：无法确认是优化起效还是环境变化、缓存预热、随机波动。

**识别**：报告中无基线数据。

**避免**：先测基线，记录环境，再改动，再测。

### 2. 单次测量

**现象**：只跑一次就下结论。

**为何错**：随机噪声可达 10-20%。

**识别**：报告中无样本数、无方差。

**避免**：至少 3 次独立运行，报告中位数与方差。

### 3. 混合变量

**现象**：同时改模型精度、batch size、引擎版本。

**为何错**：无法归因到具体变量。

**识别**：变更列表有多项，结论归因单一原因。

**避免**：A/B 对比只改一个目标变量。

### 4. 理论当实测

**现象**：「理论上能达到 X TFLOPS」当作实际性能。

**为何错**：理论峰值需要完美条件，实际有框架开销、内存瓶颈、调度损耗。

**识别**：数字接近硬件规格书，无实测命令。

**避免**：理论用于对比实测的效率，不当结论。

### 5. 冷启动当稳态

**现象**：把包含模型加载的首次运行当吞吐。

**为何错**：冷启动包含一次性成本（加载、编译、预热），不代表持续吞吐。

**识别**：吞吐异常低，未提 warmup。

**避免**：warmup 后再计时，或分别报告冷启动与稳态。

### 6. 客户端瓶颈误判

**现象**：端到端延迟高，断言服务端慢。

**为何错**：未分离网络 RTT、客户端序列化、服务端处理。

**识别**：GPU 利用率低但延迟高。

**避免**：服务端埋点，分离各阶段时间。

### 7. 精度不足测零开销

**现象**：「优化后延迟从 50ms 降到 50ms，无变化」。

**为何错**：计时器精度不足（如 1ms 精度测亚毫秒操作）。

**识别**：变化 <计时器精度，报告「无变化」。

**避免**：用高精度计时器，或测多次累积时间。

### 8. 不报方差

**现象**：只报单次峰值或均值。

**为何错**：无法判断稳定性与置信度。

**识别**：数字过于「整」（正好 100.0），无统计量。

**避免**：报告均值±标准差，或中位数 [P25, P75]。

### 9. 版本不明的参数断言

**现象**：「XX 引擎默认 batch size 是 Y」。

**为何错**：默认值会变，旧版经验不适用新版。

**识别**：断言行为但无版本号或来源。

**避免**：引用官方文档+版本，或声明「需确认当前版本」。

### 10. 把提升百分比当绝对值

**现象**：「延迟降低 50%」听起来很好，实际从 2ms 降到 1ms（用户无感）。

**为何错**：小基数的大百分比可能无实际意义。

**识别**：只报百分比，不报绝对值。

**避免**：同时报告绝对值与百分比，说明实际影响。

## 识别模式

审查报告时问：
- 有基线吗？
- 测了几次？
- 只改了一个变量吗？
- 是实测还是理论？
- warmup 了吗？
- 分离了各阶段吗？
- 给版本号了吗？
- 报方差了吗？
- 给绝对值了吗？
- 差异 >测量噪声吗？
