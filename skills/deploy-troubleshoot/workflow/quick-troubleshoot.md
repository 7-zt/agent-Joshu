# 快速排查：部署

默认模式。单一明确错误，已有报错信息。目标：快速定界 + 最小验证。

## 触发

- 未指定模式时的默认。
- 单一报错、局部问题、现象明确。

## 前置条件

- 有具体错误信息或失败现象。无报错、说不清现象时，先帮用户把现象描述成可核查形式（何时、何地、预期 vs 实际）。

## 步骤

1. 提取错误关键行（含时间戳与上下文），原样引用。
2. 采最小环境快照（只采与报错相关的类别，常用命令见 SKILL.md 参考文档导航表 environment-snapshot）。
3. 按报错信号直接检查对应层的高概率原因（最多 3 个假设），每个假设设计一个最小验证。
4. 验证通过 → 给根因 + 解决方案；不通过 → 报告已排除项，建议升级系统排查。

## 输出格式

```text
现象
- 原样错误引用 + 位置

已验证结论（0-3 条）
- 结论: …
  证据: 命令五元组 / 日志行
  解决: 步骤 + 预期结果 + 回退 + 风险（标注 L2/L3 需授权）

已排除
- 假设 → 排除证据

待确认
- …（含需要的下一步验证）
```

## 停止规则

- 3 个假设验证完仍未定位就升级系统排查，不继续盲试。
- 不猜根因；每个结论挂证据。
- L2/L3 命令给文本待确认，不自动执行。
