# 系统排查：部署

重型系统性排查。**仅用户显式触发**，或快速排查升级。从头逐层收敛，全程记录。

## 触发

- 用户明确说「系统排查」「完整诊断」「从头排查」。
- 快速排查 3 个假设验证后未定位。

## 步骤

### 1. 问题登记

写下：故障现象（预期 vs 实际）、影响范围、开始时间与变更历史（「之前好的吗？中间改了什么？」）、复现条件。

### 2. 完整环境快照

采集完整环境信息（见 SKILL.md 参考文档导航表 environment-snapshot）：硬件、OS、驱动、软件版本、容器、配置文件关键部分。

### 3. 复现确认

最小化复现：剥离无关组件，找到能稳定触发（或统计出触发率）的最小路径。复现不稳定时记录触发条件与频率，不假装可稳定复现。

### 4. 分层扫描

按 硬件 → 驱动 → 系统 → 容器/运行时 → 依赖 → 服务 → 应用 逐层检查，每层：

- 该层的健康检查命令（L0 只读优先）；
- 异常信号 → 假设 → 验证 → 记录；
- 该层干净则明确记录「已排除」再上移/下移。

### 5. 变更三问

对每个可疑点问：最近改过吗（配置/版本/环境）？文档说应该怎样（引官方文档，标注版本）？最小验证是什么？

### 6. 根因确认

候选根因必须通过「反向验证」：按根因推导应有其他可观测现象，检查它们是否成立。成立才升级为根因；只解释了原始报错不算。

### 7. 解决与收尾

解决方案按 L0-L3 分级授权执行；执行后验证原始复现路径已消除；记录 workaround 的临时性与触发条件。

## 输出格式

```text
结论
- 根因: …（已反向验证）
  证据链: 每步的命令五元组
  解决: 步骤 + 验证结果 + 回退 + 风险

分层记录
- 硬件: [排除/异常+证据] …
- 驱动: …
- 系统: …
- 容器: …
- 依赖: …
- 服务: …
- 应用: …

复现
- 最小复现路径 + 触发率

遗留
- workaround 清单（临时性说明）、待确认项
```

## 停止规则

- 根因未反向验证不写「根因」，写「最可能原因（已排除 A/B，未排除 C）」。
- 不跳层；每层排除要有记录。
- 不为收敛而编造解释；「未定位 + 下一步计划」是合法结论。
