# 复现与二分

最小化复现、变更历史二分、复现率统计。

## 最小化复现

**目标**：找到能稳定触发问题的最小条件集。

**步骤**：
1. 记录当前完整复现路径
2. 逐项移除组件/步骤
3. 每次移除后测试是否仍复现
4. 保留所有必要项，移除所有非必要项

**示例**：
```
初始：多用户、复杂配置、大模型、长序列 → 失败
移除：单用户 → 仍失败
移除：简化配置 → 仍失败
移除：小模型 → 不失败了
结论：与模型大小相关，其他无关
```

**价值**：
- 排除干扰因素
- 加快验证速度
- 明确根因范围

## 复现率统计

**不稳定复现**：
- 测试N次，记录成功/失败次数
- 计算复现率：失败次数/总次数
- 报告：「10次中8次复现（80%）」

**触发条件**：
- 首次启动必现 vs 运行一段时间后
- 特定输入 vs 随机输入
- 高负载 vs 低负载

## 变更历史二分（Git bisect风格）

**适用**：「之前好的，现在坏了」

**步骤**：
1. 确认好版本（last known good）
2. 确认坏版本（first known bad）
3. 二分查找中间版本
4. 测试该版本是否有问题
5. 根据结果调整区间，重复

**示例**：
```
v1.0（好）─────v1.5─────v2.0（坏）
            测试v1.5 → 坏
v1.0（好）───v1.2───v1.5（坏）
          测试v1.2 → 好
         v1.2（好）─v1.3─v1.5（坏）
                 测试v1.3 → 坏
                v1.2─v1.25─v1.3
               锁定：v1.25引入问题
```

**配置/环境二分**：
- 对比好环境与坏环境配置
- 逐项同步配置项
- 找到导致问题的配置差异

## 对照实验

**设置**：
- 对照组：好的环境/版本
- 实验组：坏的环境/版本
- 单变量：只改一个疑似因素

**验证**：
- 在对照组引入变化 → 能否复现问题
- 在实验组移除变化 → 能否消除问题
- 两个方向都验证，增强置信度
