# 解决、回退与收尾

方案分级、执行验证、回退准备、问题闭环。

## 方案分级

### Workaround（临时方案）

**特征**：
- 绕过问题而非解决根因
- 可能有副作用或限制
- 需要后续根本解决

**示例**：
- OOM → 降低batch size（治标不治本）
- 端口冲突 → 换端口（未清理占用进程）

**记录要求**：
- 明确标注「临时方案」
- 说明适用条件与限制
- 给出触发根本解决的条件

### 根本解决

**特征**：
- 消除根因
- 无副作用或可接受代价
- 通过验证

**验证方法**：
- 原始复现路径不再触发
- 压力测试稳定
- 监控指标恢复正常

## 执行前准备

### 回退方案

每个变更必须有回退方法：

**配置变更**：
```bash
# 备份
cp config.yaml config.yaml.backup.$(date +%Y%m%d_%H%M%S)
# 变更
vim config.yaml
# 回退
cp config.yaml.backup.YYYYMMDD_HHMMSS config.yaml
```

**服务重启**：
- 确认服务管理方式（systemd/supervisor/docker）
- 测试回退命令可用

**版本变更**：
- 记录当前版本号
- 准备降级命令

### 变更窗口

**高风险变更**：
- 选择低峰时段
- 准备监控
- 有人值守

## 验证标准

### 功能验证

- 原始故障场景不再复现
- 核心功能正常
- 健康检查通过

### 性能验证

- 延迟/吞吐恢复正常
- 资源使用在预期范围
- 无新的异常告警

### 回归验证

- 其他功能未受影响
- 相关系统正常

## 问题闭环

### 文档更新

**更新运维文档**：
- 新的配置参数
- 新的监控指标
- 新的已知问题

**更新troubleshooting文档**：
- 症状→根因→解决方案
- 避免重复排查

### 监控改进

**加监控指标**：
- 能早期发现此类问题的指标
- 告警阈值

### 根因消除

**临时方案升级**：
- 计划根本解决时间
- 跟踪状态

**系统改进**：
- 配置校验
- 自动化检查
- 资源预留

## 报告模板

```markdown

- 故障现象
- 影响范围
- 持续时间

## 根因
- 定位过程简述
- 根本原因
- 为何发生

## 解决方案
- 采取的措施
- 是否根本解决
- 如为workaround，说明限制

## 验证结果
- 复现路径验证
- 功能验证
- 性能验证

## 后续行动
- 监控改进
- 文档更新
- 根本解决计划（如适用）
```
